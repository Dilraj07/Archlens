## 1. Summary of AI Tooling Usage

In compliance with the CodeMyFYP Hackathon regulations, this document outlines how AI tools were utilized during the conception, development, and testing of ArchLens.

| Tool | Purpose / Area Used | What We Verified & Implemented Ourselves |
|---|---|---|
| **Antigravity / LLM Agent** | Architectural design, boilerplate generation for React Flow nodes, drafting initial mission copy | Hand-coded and validated the pure M/M/1 queueing engine math, cycle detection, topological sorting, and Leitner-box scheduling algorithms. Every formula is backed by automated Vitest tests. |
| **Runtime LLM Gateway (`/api/tutor`)** | In-situ Socratic mentor and Senior On-Call Incident mentor | Implemented defensive client-side validators (`validate.ts`) that discard any response where numbers deviate by more than $\pm 2\%$ from engine deltas or reference invalid nodes. Built deterministic template fallbacks (`templates.ts`) to ensure 100% functionality without API connectivity. |
| **Spoiler Guard (`spoilerGuard.ts`)** | Incident Mode integrity protection | Filtered root-cause leakage to ensure students diagnose failures from observed symptoms rather than AI hints. |

## 2. Core Integrity & Ground Truth Guarantee

ArchLens was specifically engineered around the principle that **the AI is not the ground truth; the deterministic engine is.**

1. The mathematical simulation engine contains **zero LLM dependencies** and runs deterministically in $< 1\text{ms}$.
2. The AI tutor is strictly constrained to explaining deltas generated by the simulation engine.
3. Every engineering blueprint is cited against verified public post-mortems and architecture blogs (see `docs/sources.md`).
